- Lead with the answer; plain sentences -> rule:owners-rules
- ASCII only, so no em dashes -> rule:code-standards
- Waits said aloud in the reply -> rule:delegated-decisions
- Memory file shape and size -> rule:correction-loop

How the owner wants threads to read (preferences, kept here):
- **One plain question per decision.** One short line per option, then a recommendation. Do not stack several decisions in one question.
- **Every milestone goes out as a visible message, and long work gives a short status at each step.** In a thread, plain assistant text may never reach the owner; only a posted reply (and the status checklist) does. Post a short reply when an agent's result is integrated, a fix lands, or a decision is needed, and a one-line status as each step of a long run starts or ends - unseen work reads as a stall.
- **Nothing by hand** (see [[communication-style]]): Claude runs the step, or hands over the exact commands; outward acts stay the owner's; learning projects are left out.
- **No throwaway drafts in the project library.** The host has no delete tool there, so a draft put in the library stays; keep drafts in the scratch folder and put only finished outputs there.
