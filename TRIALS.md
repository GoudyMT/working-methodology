# Trial Rules

A new kit rule ships as a trial (rule:kit-standards #7). It becomes standard once a second
project has used it cleanly, or when the owner promotes it directly. A trial that a project could not use cleanly
is reworked or retired at the next kit release.

| Rule | Kit version | First project | Second project | Status |
|---|---|---|---|---|
| Mid-model reviewers for roles other than security and the novel lens (rule:test-and-review-cadence) | 1.8.0 | course project | - | Open: counting real findings per model in the sweep log |
| Standing grants: outward acts the owner names run without a yes per act, checked, logged and reported after (rule:standing-grants, A27) | 1.13.0 | the kit repo (autopilot trial) | - | Open: autonomy.mjs ships, but every act asks while the ledger is advisory; only the owner can change that (plan kit-autopilot) |

## Promoted directly by the owner

- 0.4.0: the kit hooks, the rule sort, one home per rule, briefs from one source, merge-and-retire, slips become
  guards, trial before standard, skills by case, credited backups, vault backup. The owner made these standard at
  once, so they skip the trial.
- 0.5.0: summary, not tallies, in PR bodies and other outward summaries.
- 0.6.0: the speed review (decide copy and size ranges at plan approval, one review lead, the load guard, a proved
  related-tests hook, side-by-side gate steps, no skipped builder checks, a bounded combined fix check), and one
  session per prong with agents only where they pay off.
- 0.7.0: one size request per plan with one end check (trim or lower), and the preview tested by stakes (emulation
  by default, the owner's device for the cases a hand must judge).
- 1.0.0: rule modules - the core and modules, rule IDs, find and tags, the build, safe retire, old-layout fold-back
  (plan rule-modules, approved by the owner).
- 1.12.0: auto-fix by default and auto-merge on the owner's yes; outside repos read, never installed; fact-check
  and diagrams; the craft floor; standby plugins; the real start load and its cap; the context budget; team
  questions; the project map; one kit skill per job (ui-craft, ui-review, debugging, plan-feature, tdd) and the
  checks as scripts (names, tracking caps, parking lot, plan evidence, suggested cases). The owner approved each
  on 2026-10-31; the first real use of each new skill is its proof.
